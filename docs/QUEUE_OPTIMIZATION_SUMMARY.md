# 分析队列优化总结

**优化日期**: 2026-01-23  
**问题**: 分析队列频繁满载，导致大量分析任务被跳过  
**状态**: ✅ 已完成

---

## 🔍 问题分析

### 原始配置
- **分析队列容量**: 5,000 个任务
- **工作线程数**: 5 个线程
- **分析结果队列**: 5,000 条记录

### 瓶颈原因
1. **数据流入速度**: 600个订阅（200币种 × 3周期），峰值时瞬时产生大量任务
2. **处理速度慢**: 每个分析需要5-15秒（查询3个周期的历史数据 + 协整检验）
3. **队列容量不足**: 仅支持25秒的峰值缓冲
4. **可见性差**: 缺乏实时队列健康监控

---

## ✅ 优化方案

### 1. 队列容量优化（扩容3倍）

| 队列类型 | 优化前 | 优化后 | 提升 |
|---------|-------|-------|------|
| 分析任务队列 | 5,000 | 15,000 | 3x |
| 分析结果队列 | 5,000 | 10,000 | 2x |
| K线缓冲队列 | 10,000 | 10,000 | - |

**效果**: 
- 分析队列支持峰值缓冲时间从 25秒 → 75秒
- 结果队列支持峰值缓冲时间从 25秒 → 50秒

### 2. 工作线程优化（提升3倍）

```python
# 优化前
num_workers = int(os.getenv('ANALYSIS_WORKERS', '5'))  # 默认5个

# 优化后
num_workers = int(os.getenv('ANALYSIS_WORKERS', '15'))  # 默认15个
```

**效果**:
- 理论处理能力从 20-60任务/分钟 → 60-180任务/分钟
- 提供 300%+ 容量余量

### 3. 队列健康监控（新增功能）

**新增监控线程** `_monitor_queue_health()`:
- 每60秒输出队列状态
- 实时监控3个队列的使用率
- 使用率超过80%时自动发出警告
- 提供优化建议（如增加工作线程数）

**环境变量配置**:
```bash
export QUEUE_MONITOR_INTERVAL=60      # 监控间隔（秒，默认60）
export QUEUE_WARNING_THRESHOLD=0.8    # 警告阈值（默认80%）
```

**监控输出示例**:
```
📊 队列健康监控 | K线: 234/10000 (2.3%) | 分析: 1234/15000 (8.2%) | 结果: 45/10000 (0.5%) | 丢弃统计: 分析队列0 结果队列0
```

### 4. 增强日志可见性

#### 4.1 批量写入日志增强
```python
# 优化前
f"批量写入: {count} 条K线 | 缓冲队列: {self.kline_buffer.qsize()}"

# 优化后
f"批量写入: {count} 条K线 (去重前: {batch_count}) | "
f"K线队列: 234/10000 (2.3%) | "
f"分析队列: 1234/15000 (8.2%) | "
f"结果队列: 45/10000 (0.5%) | "
f"总写入: {total}"
```

#### 4.2 队列满警告增强
```python
# 优化前
logger.warning(f"分析队列已满，跳过分析: {symbol} @ {timeframe}")

# 优化后
logger.warning(
    f"分析队列已满，跳过分析: {symbol} @ {timeframe} | "
    f"队列: 15000/15000 (100.0%)"
)
```

## 🚀 使用建议

### 1. 环境变量配置（可选）

```bash
# 分析工作线程数（默认15，可根据CPU核心数调整）
export ANALYSIS_WORKERS=20

# 队列监控间隔（默认60秒）
export QUEUE_MONITOR_INTERVAL=60

# 队列警告阈值（默认0.8即80%）
export QUEUE_WARNING_THRESHOLD=0.8
```

### 2. 动态调优策略

**如果队列使用率持续 > 80%**:
1. 增加 `ANALYSIS_WORKERS`（建议步长5）
2. 检查数据库查询性能（索引、连接池）
3. 考虑进一步扩大队列容量

**如果CPU占用过高 (>80%)**:
1. 降低 `ANALYSIS_WORKERS`
2. 优化分析算法（缓存、向量化）

### 3. 监控指标

关注以下日志指标：
- `📊 队列健康监控`: 实时队列状态
- `⚠️ 分析队列使用率过高`: 需要扩容信号
- `分析队列已满，跳过分析`: 任务丢弃警告
